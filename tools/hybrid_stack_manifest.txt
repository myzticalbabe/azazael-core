# Hybrid Python stack manifest — compiled packages, pinned to validated versions.
#
# WHY THIS EXISTS
# ---------------
# The free-threaded (3.14t) and GIL (3.14) interpreters are installed in the
# SAME directory and share ONE site-packages:
#
#   .../Programs/Python/Python314/python.exe       -> .cp314-win_amd64.pyd
#   .../Programs/Python/Python314/python3.14t.exe  -> .cp314t-win_amd64.pyd
#
# Each interpreter recognises only its own ABI suffix, but pip installs one
# build per package and uninstalls the other. The result is a package that
# works on one interpreter and breaks on the other with nothing visible in
# `pip list`.
#
# USAGE
#   python tools/install_dual_abi.py --manifest tools/hybrid_stack_manifest.txt
#   python tools/install_dual_abi.py --manifest tools/hybrid_stack_manifest.txt --verify
#
# TIERS the installer resolves automatically
#   dual        both ABIs published at this version -> install one, overlay the
#               other. Both interpreters work.
#   pure        pure-Python wheel -> ABI-independent, works everywhere.
#   ft-priority one ABI published, but the two builds' untagged support DLLs
#               differ, so they cannot share a directory. The free-threaded
#               build is kept because 3.14t is the project's mandated runtime.
#   gil-only    only a GIL build exists upstream. 3.14t cannot load it.
#
# See NEURAL_MESH_GAP_AUDIT_2026-09-14.md section 6.6.
