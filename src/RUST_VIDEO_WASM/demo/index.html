One music video, four places the Rust/WASM can live

Every panel below runs the same clip. What changes is which layer decodes it and which layer owns the pixels.

Verdict: the default. The only architecture here that streams a file of any length — 120 KB of WASM for the whole visual layer.

idle

The <video> element does the H.264 and AAC work. Rust receives 1024 PCM samples, computes 32 band energies with a Hann-windowed DFT, and renders an additive field at 60 fps — 120 KB of WASM for the whole visual layer. This is the only architecture here that streams a file of any length.

Three defects this panel paid for, kept as regression tests: a 32-bit float DFT phase that turned music into noise (fixed by exact integer reduce + f64); a mirrored band axis that lit both ends of the frame (fixed by mapping 0..Nyquist, tone in band 4 leaves band 27 dark); linear magnitudes at 3 dp that rounded 34% of the field to black (fixed by storing log power). The readout names the peak band and its measured Hz, derived from this device's live sample rate — never a remembered number.

Verdict: works, wrong for songs. No media element, no network after load — and a payload that grows with every frame instead of every shot.

No media element at all: the frames are JPEGs inside one AVFB blob, decoded by jpeg-decoder compiled into the module. It works, and it is the wrong default for a song — the blob is 0.54 MB/s — about 119 MB for this track at 640×360, three-and-a-half times the 33.82 MB mp4 that holds it at 720p, because stills are not inter-coded.

Verdict: the useful one for effects — the browser decodes, Rust rewrites every pixel.

The useful architecture: the browser decodes and Rust rewrites the frame. Two transports, and the readout names the one that actually ran. canvas is drawImage → getImageData → process_frame_rgba → putImageData, which is a GPU→CPU readback of RGBA. WebCodecs is new VideoFrame(video) → copyTo({format:"I420"}) → i420_to_rgba, so Rust receives 1.5 bytes per pixel instead of 4, with the coded strides passed through rather than de-strided in JS.

Verdict: correct container / full decode. A packed stream parsed in Rust — or ffmpeg itself compiled to wasm (30.9 MB of entropy decoder, not the 120 KB crate).

Two sources, one reader. The first button replays a pre-packed AVRD stream. The second loads ffmpeg.wasm, decodes the mp4 in this page to a headerless RGB24 stream (stream_frame_count / unpack_stream_frame), and plays it with no media element anywhere. That is a full decode with no native video pipeline — the entropy decoder is ffmpeg compiled to wasm, 30.9 MB of it, not the 120 KB crate. node tools/fetch_ffmpeg.mjs vendors it; the panel says so plainly if it is absent rather than failing silently.
