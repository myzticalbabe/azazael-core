❓ FREQUENTLY ASKED QUESTIONS

What is Azazael and what does it do? ▼
Azazael is a distributed computing framework that provides intelligent monitoring, analysis, and optimization capabilities across multiple system tiers. It uses "worms" (specialized agents) to perform tasks ranging from system resource monitoring to code analysis, with ML-driven optimization through the HYDRAMETA layer. The framework is self-optimizing and self-healing, meaning it continuously improves its own performance and recovers from errors automatically.
What's the difference between WORMS, CLUSTERS, and METAWORMS? ▼
WORMS are individual agents that perform specific tasks like monitoring CPU usage (SYSTEMZ), tracking processes (PROCESSZ), or crawling files (WORMZ).

CLUSTERS are coordinated groups of worms that work together for complex operations, like the SYSTEM CLUSTER which combines SYSTEMZ, PROCESSZ, and DISKZ for comprehensive health monitoring.

METAWORMS operate at a higher level, analyzing the output of other worms and providing metadata extraction, dependency mapping, code metrics, and error detection.
How does the 6-stage pipeline work? ▼
The pipeline is a continuous optimization loop:
1. DISCOVERY - Scans and identifies targets for analysis
2. ANALYSIS - Metaworms process the target data
3. OPTIMIZE - Genetic algorithms tune parameters
4. VALIDATE - Error checking and quality assurance
5. DEPLOY - Execution of optimized operations
6. FEEDBACK - Results feed back into the system for continuous improvement
What is HYDRAMETA and how does ML optimization work? ▼
HYDRAMETA is the ML engine that powers Azazael's self-optimizing capabilities. It uses genetic algorithms to evolve optimal worm execution parameters. The system maintains a population of parameter configurations, evaluates their fitness based on execution metrics, and applies crossover and mutation operations to improve performance over generations. This allows Azazael to discover optimal worm sequencing and resource allocation strategies automatically.
What are the 24 HORUS animation protocols? ▼
HORUS protocols are visualization formats for presenting system data. They include Matrix View (binary cascades), Graphviz graphs, Timelines, Heatmaps, and many more. Each protocol is optimized for different data types - some for real-time monitoring, others for historical analysis or report generation.
How does TERENCE error resolution work? ▼
TERENCE uses pattern matching against a database of 50K+ known error patterns, combined with a Deep Q-Learning RL agent. When an error occurs, it builds a causal graph to understand the root cause and either suggests fixes or applies them automatically with 90% success rate. The system learns from each resolution, improving its capabilities over time.
Can Azazael run on multiple platforms? ▼
Yes! Azazael supports Windows, Linux, and macOS through the PERSEPHONE deployment system. The core functionality is cross-platform, with platform-specific implementations for system-level operations. Database adapters support SQLite, Redis, PostgreSQL, ElasticSearch, and InfluxDB.
What execution strategies are available? ▼
Five strategies control how worms are executed:
Round Robin - Sequential execution for predictable behavior
Performance - Fastest worms run first
Resource-Aware - Load-balanced based on system resources
Randomized - Chaos mode for testing resilience
ML-Optimized - Predicted best sequence based on historical data

⚡ PERFORMANCE OPTIMIZATION TIPS

Use --interval wisely: Higher intervals reduce CPU overhead but increase data staleness.
For large codebases, use --delta scanning instead of full rescans to save time.
Enable --persist to cache results and speed up subsequent analysis operations.
Use cluster modes (e.g., --cluster system) instead of running individual worms for coordinated operations.
Configure database backends (Redis, PostgreSQL) for better performance with large datasets.
Avoid running all worms simultaneously on resource-constrained systems. Use resource-aware scheduling instead.

⚡ Optimized Monitoring Command

azazael monitor --cluster system --interval 10s --persist --output influxdb
This balances data freshness with system overhead and enables historical analysis.

🔧 TROUBLESHOOTING COMMON ISSUES

Worm fails to start - "Module not found" error ▼
Ensure dependencies are installed: pip install -r requirements.txt
Check PYTHONPATH includes the Azazael installation directory.
Verify the worm configuration file exists in ~/.azazael/worms/
High memory usage during large scans ▼
Reduce --batch-size to process smaller chunks.
Enable --streaming for memory-efficient processing.
Use SQLite instead of in-memory storage for very large datasets.
Consider increasing swap space for memory-mapped operations.
TERENCE unable to resolve error patterns ▼
Ensure the pattern database is up to date: azazael terence --update-db
Check network connectivity if using remote pattern service.
Review logs for more detailed error context.
Consider contributing new patterns using --learn-from-fix
Genetic algorithm not converging ▼
Increase --generations limit for complex optimization problems.
Adjust --mutation-rate - too low causes premature convergence.
Verify fitness function is properly configured.
Check that population diversity is maintained.
Database connection failures ▼
Verify database credentials in ~/.azazael/config.yaml
Check network connectivity and port accessibility.
Ensure database server is running and accepting connections.
Review firewall settings for database ports.
Use --test-connection to diagnose issues.
