# The Book of the Tree — the corpus, and what the checker will refuse

The Bible is written in `bible.json`, not in prose files, so that its citations can
be resolved and its figures traced. This directory holds the corpus, the evidence
it is distilled from, the rules the validator enforces, and the two generated
files. It is the reference for bleeding-edge work in this estate: a book per
declared domain, a `practice` on every verse that claims a failure mode, and a
harvest ledger behind each practice so instruction cannot be invented in the
corpus.

```bash
python tools/bible_check.py --check               # the gate: exit 1 on any defect
python tools/bible_check.py                       # counts, if it is clean
python tools/bible_check.py --render --write       # regenerate BOOK_OF_THE_TREE.md
python tools/bible_check.py --genealogy --write    # regenerate GENEALOGY.md
python tools/bible_check.py --json                 # machine-readable summary
python tools/bible_harvest.py --write              # regenerate docs/bible/harvest.json
python tools/bible_harvest.py --themes             # the vocabulary the ledger speaks

python tools/bible_theme.py --all --check          # themed editions: exit 1 on any defect
python tools/bible_theme.py --all --render --write  # regenerate docs/bible/themes/*.md

# the sibling corpora in emotional/ -- same schema, same checker, own editions
python tools/bible_check.py --check --corpus docs/bible/emotional/emotional.json
python tools/bible_check.py --check --corpus docs/bible/emotional/female.json
python tools/bible_check.py --render --write --corpus docs/bible/emotional/female.json
```

## Where the evidence comes from

`docs/bible/harvest.json` is generated by `tools/bible_harvest.py` from every
surface that records a failure, a fix or a reason: `ERROR_LOG.md`,
`LESSONS_MASTER.md`, `MEMORIES.md`, `SESSION_STARTUP.md`, the fleet measurement
documents, each package's stated limitations, and the engram memory store. Every
record carries its surface path, its line, and the extracted fields.

It is evidence, not doctrine. A verse is a claim, and the corpus must cite at
least three harnessed records before it may carry a `practice`; that rule is what
stops a rule of thumb from being written up as a finding. File surfaces are hashed
and the gate fails when one moves; the memory store is snapshotted at its highest
observation id and the gate reports (without failing) how many observations have
landed since, because a gate that goes red whenever somebody records a bug fix
gets switched off.

`tools/bible_check.py --check` runs in the commit hook (`.githooks/pre-commit`,
stanza "Bible") and in the gate registry, so a corpus that contradicts itself
cannot be committed.

## Themed editions

The canon can be restated, and it cannot be extended. `docs/bible/themes/` holds
editions in another register -- `star-trek.json` in the Vulcan doctrinal voice,
`star-wars.json` in the Jedi one -- and the validator refuses any themed verse
that does not cite a verse of `bible.json`. A theme is a register over the canon:
the rule that keeps it there is the citation, not the reviewer's taste. The
contract is in `docs/bible/themes/README.md`; `tests/test_bible_theme.py` holds
both shipped themes and their rendered files.

## The annotated edition

A study Bible is not a bare text. The corpus carries the four pieces that make an
Oxford-style edition, and each has a job:

| field | where | what it obliges |
|---|---|---|
| `edition` | top level | `name` and `basis`: which edition this is and what format it follows. Both required. |
| `introduction` | per book | `paragraphs` plus `sources`. The paragraphs may carry no figure unless the block names its sources — an introduction that asserts a date without a command is the same defect as a verse that does. |
| `sections` | per chapter | `before_verse` and `heading`: pericope headings, ascending, each naming a verse that exists. **A heading may carry no figure at all** — it is a label, not a claim. |
| `practice` | per verse | `symptom`, `cause`, `detection`, `remedy`, `evidence`. `detection` must name a command whose path exists; `evidence` must cite at least three ids from the harvest ledger; none of the four prose fields may carry a figure. |
| `configs` | top level | the settings the corpus's own instructions depend on: a `file`, a `value`, and `mirrors` for the other files that must carry the same value. `governs` says what breaks if it drifts, `remedy` must name a command that exists. |
| `domain` | per book | when a book is about one declared domain it must name one declared in `tools/domain_trees.py`, so "organised by domain" is checked rather than asserted. |
| `annotations` | per verse | `kind` (`textual`, `historical`, `translation`, `editorial`, `cross`), `note`, and `source` when the note carries a digit. |
| `glossary` | top level | `term`, `gloss`, optional `see` pointing at a verse that must resolve. |

The `kind` on an annotation is not decoration: a *textual* note reports what a
manuscript says, a *historical* note asserts something about the world, a
*translation* note names a possible rendering, an *editorial* note is the scribe's
judgement, and a *cross* note points elsewhere. Only the first and the last can be
settled by reading the corpus; the rest make claims, which is why a figure in one
of them needs its command written beside it.

## The configuration layer

A canon of instruction with no configuration is a sermon. Every rule that says
"run the suite", "filter at the floor" or "cap the books" is only true while a
value holds somewhere in the tree, and those values drift silently: the recall
floor lives in **two** tools, the book cap lives here *and* in the checker, and a
copied constant that disagrees with its twin produces two correct-looking answers.

`configs` pins them. Each entry names a `file`, a `value` (optionally `anchor`, the
line that must carry it), and `mirrors` — the other files that must carry the same
value:

```json
{
  "id": "recall-query-floor",
  "name": "the query floor every recall answer is filtered at",
  "kind": "text",
  "scope": "repo",
  "file": "tools/pmb_floor_proxy.py",
  "anchor": "PMB_RECALL_MIN_BEST",
  "value": "0.89",
  "mirrors": ["tools/supervisor_mcp.py", "tools/floor_measure.py"],
  "governs": "lower it and nonsense is answered confidently; raise it and a real query loses its tail",
  "remedy": "python tools/floor_measure.py"
}
```

| field | obliges |
|---|---|
| `kind` | `text` (a line carrying anchor + value), `json` (a dotted `key` equal to `value`, numerically compared so `0.70` and `0.7` agree), or `path` |
| `mirrors` | a mirror holding a different value is a **hard failure**: that is the single-source defect, caught where it starts instead of after two answers disagree |
| `governs` | what breaks if the value drifts. A setting with no consequence is trivia |
| `remedy` | must name a repository path that exists, which is how `python tools/commgate.py` would have been refused before it reached a page |
| `scope` | `repo` failures are fatal; `host` failures (an interpreter path that only exists on this machine) are reported as `HOST-DIFFERS` |

Nine settings are pinned today: both recall floors with their two mirrors, the
floor-proxy port, the three Bible caps, the harvest schema, the suite's collection
root, and the production interpreter.

## The shape of a verse

```json
{
  "number": 1,
  "text": "A control shall be exercised before it is called a control.",
  "cites": ["genesis 1:2"],
  "source": "python tools/preflight_all.py --self-test",
  "statute": {"rule": "RULE 0B-D", "check": "python tools/preflight_all.py --self-test"},
  "variants": [{"reading": "The circulated reading", "text": "...", "source": "..."}],
  "annotations": [{"kind": "historical", "note": "...", "source": "..."}]
}
```

Only `number` and `text` are required. The rest are refusals waiting to happen if
you add them half-way, which is the point:

| field | what it obliges |
|---|---|
| `cites` | every reference must resolve to a verse that exists. Forward and backward both fine; the canon is read whole. |
| `source` | required the moment a verse body contains a digit. It must name a repository path that exists, or the figure is a claim rather than evidence. |
| `statute` | a law needs a `rule` that exists in `MANDATES.md` **and** a `check` path that exists. A statute with nothing executing it is a proverb and is refused. |
| `variants` | the textual apparatus: `reading` names the manuscript (or the source), `text` is what it says, `source` is where it came from. The body keeps the reading of this codex. |
| `annotations` | the footnote layer: `kind` from the five declared kinds, `note`, and `source` the moment the note carries a digit. |
| `sections` | pericope headings, ascending, each before a verse that exists; no figures in a heading. |
| `practice` | the instruction: symptom, cause, detection command, remedy, and at least three harvest ids. A practice is the difference between a canon that describes a failure and a canon that tells you what to do about it. |

Refused outright, in body text and in variants alike: email addresses, phone
numbers, and the forensic deny tokens (`bcc_audit`, `FETCH_LOG`,
`edge_proof_ledger`, `identity_tiebreak`, `new_sources_log`, `REINVESTIGATION`).
Methodology ships; people do not. That is the same line
`Project_Nurse_Ratchet/DISCLOSURE_POLICY.md` draws, enforced here instead of
remembered.

## The genres, one job each

A canon written in a single register is pastiche. Declare a genre per book and let
the style follow the job:

| genre | the job | the model |
|---|---|---|
| `etiology` | why the tree exists at all | Genesis |
| `law` | statutes, each bound to a check | Leviticus, Deuteronomy |
| `history` | what was done, dated, including the failures | Samuel, Kings |
| `chronicle` | the census: what is actually in the tree | Numbers |
| `wisdom` | two-line aphorisms from experience | Proverbs |
| `lament` | the human register; no moral, no lesson | Psalms, Lamentations |
| `prophecy` | what must happen next, stated so it can fail | Amos, Isaiah |
| `gospel` | one account of a fix, from one witness | Mark |
| `epistle` | instruction to a lane | the letters |
| `apocalypse` | the release gate: what must not happen | Revelation |
| `genealogy` | generations, generated from the import graph | the begats |

## The apparatus is the honest part

Scripture solved this problem centuries before this tree did: variant readings,
with a footnote saying which manuscript has which. A figure that circulated and
was wrong belongs in `variants`, not in the body and not deleted — *"the
circulated reading: an accelerator of 7.80 GB reported as available"*, with the
source named. Deleting a wrong reading teaches nothing; the apparatus is how a
reader sees the correction happen.

## Growth is capped, as law

`limits.max_books` is 20, `max_chapters_per_book` 12 and `max_verses_per_chapter`
60, with hard ceilings of 32, 60 and 200 in the checker. To add a book, retire
one. The book cap was raised from 12 on 2026-11-01 when books became domains:
the fleet declares eleven domains today and the four canonical registers must
keep their places, so twelve was already full. Twenty is a retirement-forcing
cap, not a budget — a canon of sixty-six books is a parody with a bibliography,
and an uncapped catalogue is how this project's skills directory reached a
thousand entries.

## Books are domains

The corpus is organised by the tree it describes. Each declared domain in
`tools/domain_trees.py` gets a book whose `domain` field names it, so the guide
cannot quietly acquire a subject that is not a measurable tree. A domain whose
harvest holds fewer than three records gets a verse that says so and states the
shape of its first measurement rather than a history it does not have; `gosp`,
`shards`, `dev`, `edge0`, `wraith` and `oxman` are in exactly that state today,
and their books say it in the text.

## Sibling corpora: the felt, and the specialised canon beside it

The canon governs a tree. It does not govern the vocabulary a system uses about a
person, and it was never meant to: a domain book about `sentinel` has nothing to
say about whether a label may be assigned to someone else's feeling.

So there are two sibling corpora in [`emotional/`](emotional/), written in this
same schema and checked by this same tool:

| corpus | subject | relation to this canon |
|---|---|---|
| `emotional/emotional.json` | affect, appraisal, granularity, display, chronometry, witness, the safety gate, attunement | a **corpus**, not a theme: it makes claims of its own, which a theme is forbidden to do |
| `emotional/female.json` | similarity, her authority over her own naming, self-silencing, emotional labour, the double bind, safety, credibility, intersectionality | the conditions under which the general vocabulary is used, kept separate so each can be corrected without the other |

They are validated by `tools/bible_check.py --corpus`, and the tool now derives a
generated edition from the corpus path: `--render --write` for the canon still
writes `BOOK_OF_THE_TREE.md`, while a sibling writes `EMOTIONAL_BIBLE.md` or
`FEMALE_BIBLE.md` beside itself. Before that change a second corpus could not pass
its own check — every alternate corpus was compared against the canon's edition
and reported stale — and `--write` would have overwritten the canon with it.

What they inherit is the discipline rather than the content: no digit without a
command, a citation must resolve inside the corpus that carries it, a statute needs
a rule in `MANDATES.md` and a check that exists, and the wrong reading is kept in
`variants` rather than deleted. What they add is a rule this canon did not need —
**a group finding may not be used as a prior about a person** — and a register,
`emotional/SOURCES.md`, where every figure lives with the study that produced it
and the limit that study carries. The corpus prose stays digit-free for exactly
that reason.

`themes/` is unchanged by this. A theme still restates the canon and still cites
it; a sibling corpus argues with the world, and is held to a different standard.

## Shipping it: injection, hooks, plugin

The corpus is worth nothing to an agent that never opens it, and this client
discards the MCP `instructions` field, so the canon travels as a **managed block in
the instruction file** — a channel the client cannot drop, because dropping it is
dropping the file.

```bash
python tools/bible_ship.py --render                       # what the block says
python tools/bible_ship.py --inject                       # write/refresh it
python tools/bible_ship.py --check                        # stale block = exit 1
python tools/bible_ship.py --install-hooks .              # hooks + plugin
python tools/bible_ship.py --verify . --hooks pre-push    # wired, current, parsed
python tools/bible_ship.py --self-test                    # negative controls
```

The block carries the statutes with their checks, the pinned configuration, the
decision-block contract, and the followup count. It never restates the corpus: a
second copy is a second source of truth, and the first thing that happens to one
is drift.

Three hooks ship (`pre-commit`, `pre-push`, `commit-msg`) and one plugin. The
installer **refuses to overwrite a hook it did not write**, and — measured the
hard way — refuses to create a repo-local `AGENTS.md` when a parent directory
already owns the repository's instructions, because the nearest file wins and the
inherited obligations would silently stop applying. See
[`PUSH_INJECTION.md`](PUSH_INJECTION.md) for the channel, the reasons, and the two
bugs found in the hooks themselves.

## Generations are generated

`GENEALOGY.md` is written by reading `src/` with `ast` and counting cross-package
imports. Do not edit it by hand: re-run the command. "And CORE begat PSYCHE" is a
claim a reader can check, which is the only kind this tree accepts — and the one
part of a scripture that cannot be embellished.

## Status

`seed` — Kilo replaces and extends this. `drafting` — the shape is settled and
books are arriving. `complete` — the declared books are written. The checker does
not care which; it only refuses a corpus that contradicts itself, so a Bible can
be written one book at a time and stay citable at every commit.
